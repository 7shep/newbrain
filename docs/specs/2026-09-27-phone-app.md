# Brain on your phone

Approved in chat with Zac on 2026-09-27. The Mac is often off, so the phone works with GitHub alone.

## Scope
The phone gets everything above the Map: cover story, Up next, Notes to self (Done / Tomorrow / Next week /
Drop), Projects (tap to read), Ideas (Done / Dismiss), Claude's habits (on/off), Capture (note, idea, todo,
person, habit), and reading notes. The Map, the sessions timeline and note editing stay on the Mac.

## How it fits together
- **Notes repo (private)** is the backend. It gets `phone/queue/` (one JSON file per phone action),
  `phone/state.json` (the summary the phone reads) and a GitHub Action.
- **The Action** runs on every push: it checks out the public `brain` repo, runs `app/phone.py`, which applies
  each queued action with the same `act_*` functions the Mac app uses, rebuilds `INDEX.md` and
  `phone/state.json`, and commits. A bad action goes to `phone/failed/` with its error. Captures don't run
  agents there: they're parked in `agents/pending/`. A daily run refreshes date-based fields.
- **The phone app** (`mobile/`, served from GitHub Pages) reads `phone/state.json` and notes through the
  GitHub API with a fine-grained key (notes repo only, Contents read/write) kept in the phone's local
  storage. Each tap writes a queue file, shows the change straight away, and keeps it on screen until the
  queue file is gone (applied). Changes made offline wait in the phone's outbox.
- **The Mac** (`app/sync.py`, on when the notes folder has `phone/`) pulls when `brain` starts, when the page
  asks for state, every minute on a background timer (so phone agent tasks start with no tab open; at most
  once a minute either way) and when a Claude session starts. It commits only the files Brain
  itself wrote, then pushes, rebasing and retrying if GitHub moved on. After a pull it starts agents for
  parked captures. A pull that can't rebase cleanly is aborted and shown as "Sync paused", never guessed.
  The one exception: an untracked file the pull would overwrite is dropped when it matches the incoming copy
  byte for byte (both sides created it, e.g. `daily/<date>.md`), and the pull retried; a differing one pauses.
  A clean pull that leaves the Mac ahead pushes in the background. Today's daily list, created by the day
  planner during a state read, is committed straight away so it isn't left untracked.

## Why this shape
Only one piece of code edits notes (Brain's Python), so the phone can't corrupt them and never duplicates
the parsing logic. The cost is roughly 30 seconds before a phone change is real.

## Testing
`tests/test_phone.py`: every action type applied to the example notes, captures parked not run, a bad
action set aside; Mac sync against throwaway git repos (pull + hook, commit only Brain's files, rejected
push rebased, real conflict aborted and reported).

## Voice questions (2026-10-12, Claude since 2026-10-21)

The phone now has a countdown home view, capture animations, Soft theme, and hold-to-ask microphone.
Speech recognition and speech synthesis stay browser-native. The private queue adds `ask` with an id and
text. Answers live in `phone/answers.json` (last 20) and appear in phone state. Question failures go to the
existing failed queue and do not block other actions.

The Action answers in three steps: `phone.py --prepare-asks` collects the questions and notes,
`phone.py --answer-asks` runs headless `claude -p` on the user's Claude plan (the only step that sees the
`CLAUDE_CODE_OAUTH_TOKEN` secret from `claude setup-token`), and the
normal apply step validates each answer before saving it or capturing a requested memory. A Haiku call first sorts
the questions: everyday lookups and captures go to Haiku, easy coding questions to Sonnet, and multi-step planning
or hard reasoning to Opus. Questions in one tier share a call; a question the classifier misses goes to Sonnet.
Without the secret, ordinary phone actions continue to work.

The fork's workflow template checks out `7shep/newbrain`. Updating the private notes repo's workflow and secrets is
a separate deployment step, not an edit to the public application repository.
