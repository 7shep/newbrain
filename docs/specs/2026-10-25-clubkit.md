# clubkit in Brain

**Goal:** see and work with clubkit, Alex's agent-first club monorepo, from Brain, with two separate repos joined
through clubkit's own agent layer rather than by Brain reading clubkit's code.

## Finding the repo
`app/clubkit.py` looks through non-archived project notes' `paths:` and takes the first folder whose `package.json`
has `"name": "clubkit"`. No machine path is written in this repo. No project pointing at one: no tile, no tools.

## The tile (desktop)
`clubkit.state()` adds `S.clubkit`, built from read-only sources:

- git: branch, uncommitted file count, last commit (`git --no-optional-locks`, so polling never takes the index lock);
- `catalog.json`: module name, status, summary;
- `TODOS.md`: open `- [ ]` items, continuation lines joined, code ticks and bold removed;
- `evals/results/*.json`: each run's agent, model, commit, date, task count, and clubkit/baseline passed, total and
  cost. Real runs (newest 12) are kept apart from the latest `noop` and `reference` sanity runs. Parsed summaries are
  cached by file mtime, since the files are large and never change once written.

The board tile counts working modules, shows the latest eval and recent runs, and spotlights the next TODO. Opened,
it shows the run table with the gap in points, sanity checks, module cards, the TODO list and the Ask box. Eval
results are gitignored in clubkit, so the phone (built on GitHub) never has them; `phone.py` doesn't keep the key.

## Agents with clubkit's MCP server
`Agents(extra_tools=...)` takes a function, called at each run, returning extra command args, allowlist additions and
a prompt note. `server.clubkit_tools()` returns `--mcp-config` for clubkit's server (`node --import <tsx loader as a
file URL> <repo>/packages/mcp/src/server.ts`; the server finds its repo from its own path, so the agent's working
directory doesn't matter), the five tools `mcp__clubkit__list_modules`, `get_module`, `verify_module`, `list_skills`
and `read_skill`, and `clubkit.AGENT_NOTE`. Only `task` and capture agents get them; the internship run, the reply
check and routine creation never do. The repo isn't added with `--add-dir`, so agents read and verify clubkit only
through its MCP tools and can't edit it. `verify_module` runs a module's declared verify command (its tests).

The tile's **Ask** box posts `/api/agent` with the text prefixed "About clubkit: ".
